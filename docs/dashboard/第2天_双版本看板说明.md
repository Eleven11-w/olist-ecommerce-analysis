# Excel 与 Streamlit 双版本看板说明

## 交付策略

项目使用同一份冻结数据完成两个展示版本：

1. Excel 版用于证明数据透视、汇总表、图表和业务表达能力；
2. Streamlit + Plotly 版用于证明 Python 交互看板、筛选逻辑和公开部署能力。

两种工具只改变展示层，不改变仓库内已经冻结的指标口径。

## Excel 版结构

- `经营总览`：GMV、有效订单、AOV，月度趋势、品类 Top10、州 Top10；
- `Cohort留存`：默认保留规模至少 30 的 21 个 cohort；
- `月度透视`、`品类透视`、`州透视`：按数据透视口径生成的可审计汇总；
- `销售明细`、`Cohort源数据`：源数据表；
- `使用说明`：指标定义和刷新方法。

当前自动生成器输出的是数据透视口径的汇总表，不依赖不稳定的原生 PivotTable 缓存。需要练习 Excel 原生操作时，可基于 `销售明细` 表手动执行“插入 → 数据透视表”，所得结果应与三个透视汇总页一致。

## Streamlit 版运行

```powershell
cd E:\03_Development\DataAnalyst\olist-project
python -m pip install -r requirements.txt
python -m streamlit run dashboard/app.py
```

经营总览提供月份、州、品类筛选。三个筛选器只作用于经营页；Top10 在当前筛选结果内重算。Cohort 页使用独立数据源，不受经营筛选器影响。

## 应掌握的知识

- 事实表粒度与去重计数：99,002 行不等于 99,002 个订单；
- SUM、COUNTD 和 AOV 的分子分母；
- 日期分组、Top N、排序和筛选作用域；
- 数据透视表的行、列、值、筛选器四个区域；
- Cohort 热力图、规模门槛和观察窗截尾；
- Streamlit 状态控件与 Pandas 布尔筛选；
- Plotly 折线图、横向条形图和热力图；
- 描述性结论与因果结论的边界。

## 面试可能追问

1. 为什么事实表行数大于订单数？
2. 为什么订单数必须去重，而 GMV 可以直接求和？
3. 为什么两份数据不能直接 JOIN？
4. Excel 数据透视表和 Pandas `groupby` 的对应关系是什么？
5. 为什么 Top10 要在当前筛选范围内重算？
6. 为什么 Cohort 默认排除规模小于 30 的客群？
7. 为什么第 0 月留存率一定是 100%？
8. 为什么不能直接比较早期和晚期 cohort 的完整生命周期？
9. Streamlit 如何避免每次交互都重新读取 CSV？
10. 如果 GMV 正确但订单数偏大，首先检查什么？
